## 2. Analysis of Dormant Tables (Not Mapped to Active Endpoints)

Of the 94 tables in `hms_db`, **11 tables** are not directly queried by any active API endpoint or service function. Every one of them has rows in the live database, is seeded by the seeding suite, and is mapped to an ORM model:

1. `activity_role_association` (34 rows): Seeded by [seeds/steps/activity.py](file:///C:/Users/user/OneDrive - Inspironics India/Insp Total Work/HMS-Frontend/ACX-Platform/backend/seeds/steps/activity.py). Defines role subscriptions for notifications. Unreferenced by current notification endpoints.
2. `command_type` (10 rows): Seeded by [seeds/steps/devices.py](file:///C:/Users/user/OneDrive - Inspironics India/Insp Total Work/HMS-Frontend/ACX-Platform/backend/seeds/steps/devices.py). Catalog of device command codes. Outbound commands are out of scope in HMS Web.
3. `device_command` (0 rows): Table for outbound actuation commands. Unreferenced by active routes.
4. `lock_activity_log` (5 rows): Seeded by [seeds/steps/activity.py](file:///C:/Users/user/OneDrive - Inspironics India/Insp Total Work/HMS-Frontend/ACX-Platform/backend/seeds/steps/activity.py). Physical door lock unlock event audit. Unreferenced by active routes.
5. `organisation` (1 row): Seeded by [seeds/steps/facility.py](file:///C:/Users/user/OneDrive - Inspironics India/Insp Total Work/HMS-Frontend/ACX-Platform/backend/seeds/steps/facility.py). Parent entity of `facility`. Queried via FK cascade but has no dedicated `/organisations` endpoint.
6. `room_service_request` (3 rows): Seeded by [seeds/steps/services.py](file:///C:/Users/user/OneDrive - Inspironics India/Insp Total Work/HMS-Frontend/ACX-Platform/backend/seeds/steps/services.py). Legacy IKANOS guest-room service queue. Active HMS Web uses `service_request`.
7. `room_service_request_item` (4 rows): Seeded child items of `room_service_request`.
8. `scheduler_job` (5 rows): Seeded cron jobs from legacy `caleido_scheduler`. Active Python backend runs no background scheduler.
9. `scheduler_job_execution` (6 rows): Execution history of `scheduler_job`.
10. `user_device` (4 rows): Mobile device push tokens (FCM). Unreferenced by web frontend.
11. `user_device_acl` (5 rows): User-to-device door lock access control lists.
12. `user_token` (3 rows): Legacy stateful session tokens. Unused by stateless HS256 JWT auth.
