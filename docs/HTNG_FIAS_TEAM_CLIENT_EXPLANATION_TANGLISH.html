Chapter 1

Oru Simple Story — Hotel-la Enna Nadakkudhu?

Oru hotel-la rendu software irukku nu nenachukonga.

PMS (Property Management System) Hotel-oda front desk software. Oracle Opera, Protel maadhiri vendor products. Reservation, check-in, check-out, bill ellam inga dhaan.
HMS (namma product) Rooms, guest stays, service requests, devices, energy, housekeeping ellathayum manage pannudhu.

Problem enna?

Guest Mr. Kumar front desk-la check-in pannaaru. Front desk staff andha check-in-a PMS-la enter pannuvaanga. Aana namma HMS-ku idhu theriyaadhu. Adhanaala:

  • Room innum "Vacant"-aa dhaan kaattum.
  • Room devices welcome mode-ku poagaadhu.
  • Housekeeping-ku update varaadhu.
  • Staff idhai HMS-la thirumba type pannanum. Time waste, mistakes-um varum.

Solution

PMS-um HMS-um automatic-aa pesanum. PMS-la check-in aana udane, adhu oru message-aa HMS-ku varanum. HMS adhai eduthu room-a "Occupied" nu maathanum. Indha "pesura bridge" dhaan indha project.

Hotel-oda front desk software-la nadakkura check-in, check-out ellam namma HMS-ku automatic-aa varra maadhiri oru bridge build pannirukom.
Chapter 2

HTNG Enna? FIAS Enna?

PMS-um HMS-um pesa oru common language (protocol) vendum. Hotel industry-la popular-aa rendu language irukku: HTNG, FIAS.

HTNG — "courier-la letter anuppura maadhiri"

HTNG = Hospitality Technology Next Generation. Idhu hotel industry standards.

  • Ovvoru message-um oru XML document (structured letter maadhiri).
  • PMS adhai internet / network vazhiya namma server-oda oru web address-ku anuppum (HTTP / SOAP).
  • Ovvoru message-um thani thani-aa varum. "Letter vandhuchu → reply panrom."

FIAS — "always-on phone line maadhiri"

FIAS = Fidelio Interface Application Specification. Idhu Oracle Opera maadhiri PMS-ku romba common.

  • PMS-um namma system-um oru TCP connection (continuous line) open vachirukkum.
  • Andha line-la chinna chinna text records anuppum. Udharanam: "GI|RN204|…" (GI = Guest In).
  • Line alive-aa irukkaa nu check panna "heartbeat" (naadi) messages-um varum.

Yen rendu-um build pannom?

Endha PMS vendor-oda connect pannanum nu innum decide aagala (decision HF-03). Avanga endha language pesuvaanga nu-um theriyaadhu (HF-04). Sila vendor FIAS mattum, sila vendor HTNG mattum, sila vendor rendu-um support pannuvaanga.

Adhanaala rendukkum common-aa varra parts-a (security, save, retry, monitoring) oru dhadava build pannom. Protocol-specific parts-a "vendor rules vandha udane plug panra maadhiri" ready-aa vachirukom. Vendor rules-a guess panni code ezhudhala.

Udharanam Oru vendor-oda exact XML format theriyaama guess panni code ezhudhinaa, real hotel-la wrong room-ku check-in poagalaam. Adhanaala official document vandha appuram dhaan final format fix pannuvom.
Rendu protocol-kum common foundation ready. Vendor yaarunu confirm aagi, avanga official documents kudutha udane andha protocol-a final pannuvom.

Idhu enna?

Duplicate messages, reject aana messages (wrong login, unknown hotel, bad format)
Gavanam

OUTBOUND — "Queued or sent to vendors" · demo: 3

Idhu enna?
Namma HMS vendor-ku thirumba anuppa ready panna messages (reply / update).
Calculation
Outbox table-la ellaa rows → HTNG 2 + FIAS 1 = 3. Moonum "queued".
Yen send aagala?
Anuppura part (outbox relay) start pannala. Vendor address-um configure aagala (HF-24).

PENDING — "Waiting to be processed" · demo: 13

Idhu enna?
Innum mudiyaadha incoming messages
Calculation
PENDING (worker innum edukkala) + PROCESSING (ippo process aagudhu) + AWAITING RETRY (retry-ku wait) → HTNG 8 + FIAS 5 = 13
Yen kuraiyala?
Worker run aagala. Adhanaala pending messages appadiye irukku.

FAILED — "Inbound, moved to the DLQ" · demo: 5

Idhu enna?
System "mudiyaadhu" nu give up panna incoming messages
Eppo fail aagum?
Permanent problem (wrong data, HMS rule reject) → first try-laye fail. Temporary problem (HMS busy, timeout) → 5 attempts try pannum, appavum sari aagalana fail.
Calculation
Incoming status = DEAD_LETTER → HTNG 3 + FIAS 2 = 5. Demo reason: "Rejected by HMS business rule".

AWAITING RETRY — "Scheduled for another attempt" · demo: 5

Idhu enna?
Temporary problem-naala fail aagi, automatic-aa thirumba try panna schedule aana messages
Retry gap
5 sec → 10 → 20 → 40 … max 15 nimisham. Total 5 attempts.
Calculation
Status = RETRY_WAIT → HTNG 3 + FIAS 2 = 5
Gavanam
Indha 5 messages Pending 13-kulla already count aagirukku.

DLQ — "Inbound and outbound" · demo: 5

Idhu enna?
Dead Letter Queue-la irukura ellaa messages: incoming failed + outgoing failed
Calculation
Inbound failed 5 + Outbound failed 0 = 5
Gavanam
Failed-um DLQ-um add panna koodaadhu. Failed 5 already DLQ-kulla irukku.
