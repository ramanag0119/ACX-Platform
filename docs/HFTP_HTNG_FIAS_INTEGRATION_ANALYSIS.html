1. Executive Summary

Can we integrate HFTP into our module / dashboard?
No, there is nothing to integrate
HFTP is a professional association (finance and technology). It does not operate a hotel-data service or an integration API.
Should we apply to HFTP for an API key?
No, HFTP does not issue one
No API key or developer programme from HFTP was found. Integration credentials come from the hotel's PMS vendor.
Is HTNG owned by HFTP?
No, HTNG is part of AHLA
HTNG was absorbed by the American Hotel & Lodging Association (announced March 2021). HFTP is only a partner of HTNG.
Are the specifications free?
Partly
HTNG specifications have historically been published publicly once ratified. The Oracle FIAS specification is publicly downloadable, but under Oracle licence terms. Production use needs a vendor or Oracle agreement.
Recommendation Do not apply to HFTP, and do not budget for an HFTP API key. Spend the effort on what actually unblocks the module:
  1. Confirm the target PMS vendor and product (decision HF-03). This is the single gating decision.
  2. Download the free HTNG specifications and the public Oracle FIAS specification now, for internal reference only, to reduce technical risk (no cost).
  3. Once the vendor is known, request credentials, sandbox and certification from that vendor (for Oracle OPERA: the Oracle partner programme / OHIP).
HTNG (AHLA) or HFTP membership is optional. It is useful for networking and industry visibility, but no integration needs it.

2. Background: What We Asked and Why It Matters

Our HMS has an integration module that receives guest check-in and check-out events from a hotel's Property Management System (PMS) over two industry protocols:

  • HTNG: XML messages over a web service (SOAP / HTTP).
  • FIAS: Oracle's record-based protocol over a TCP link, used by Oracle OPERA and Suite8.

The module and its five-page monitoring dashboard are built and tested on synthetic data. Two items block production:

  • HF-07 / HF-08: the HTNG schema and security profile.
  • HF-11 / HF-06: the FIAS specification and link rules.

Both depend on the vendor decision HF-03. The question was whether HFTP could supply the missing piece, or a key that lets us connect.

4. Detailed Findings

Finding 1: HFTP offers no integration API or API key verified

HFTP's public activity covers the HITEC conference, the USALI accounting standard and its vendor "stamp" licensing programme, certifications, a PII task force, a code of digital responsibility, and an AI Collective planning AI data-standards guidance. None of the sources reviewed describe an API, developer portal or key issuance.

Implication: there is nothing from HFTP to plug into the HTNG or FIAS adapters or to show on the dashboard. Applying to HFTP would not produce a credential.

Finding 2: HTNG is owned by AHLA, not HFTP verified

AHLA and HTNG announced on 25 March 2021 that HTNG would become part of AHLA, keeping the HTNG brand. AHLA material from 2025 describes HTNG as "part of AHLA". HFTP and HTNG had a 2018 partnership and merged their European conference into HITEC Europe, but they are separate organisations. In 2022 HFTP's CEO publicly referred to AHLA's takeover of HTNG.

Finding 3: HTNG specifications are documents, mostly public partly verified

Published sources state that HTNG releases ratified specifications publicly, "in most cases", with some exceptions. Some sources also say the OpenTravel-based XML is free to download. These sources are several years old. We could not load htng.org during this review, so the current download terms should be checked on the site before relying on them.

Implication for us: the public HTNG XSD / WSDL set can seed the XSD library our HTNG adapter needs (linked to HF-39). It does not close HF-07. Each PMS vendor implements its own subset (profile), and we still need that vendor's profile, endpoints and security rules (HF-08).

Finding 4: FIAS is Oracle's; the specification is public but licensed verified

Oracle hosts Oracle Hospitality Hotel Property Interface IFC8 FIAS Specification, Release 2.20.25 (May 2022) on docs.oracle.com. We downloaded and inspected it. It contains exactly what our FIAS adapter is waiting for:

  • Record formats
  • Link control records (LS / LA / LE / LD / LR / LC)
  • Timeouts
  • Connection authentication
  • TLS option
  • Database resynchronisation

However, the document carries Oracle's standard notice:

"provided under a license agreement containing restrictions on use and disclosure … Except as expressly permitted in your license agreement or allowed by law, you may not use, copy, reproduce … modify … or display any part."

Implication:

  • We can use it now as a technical reference to validate our FIAS framework against the real record and link rules. This materially de-risks HF-11 and HF-06.
  • Production use, Oracle validation and the hotel-side interface licence must go through Oracle or the hotel's OPERA contract.
  • Legal should confirm how far we may use the document before an Oracle agreement exists.
  • The hotel may run a different FIAS version, so the vendor must still confirm the record set.

Finding 5: API keys come from the PMS vendor verified

For Oracle's cloud platform (OHIP), every API call must carry an Application Key. The key is issued and managed in the OHIP Developer Portal and must not be shared across organisations. Oracle documentation and secondary sources indicate that production access also needs an Oracle PartnerNetwork (OPN) reference and/or an Oracle Cloud Marketplace listing, confirmed by e-mail to Oracle's hospitality integrations team. The sources differ on which of the two is mandatory, so this should be confirmed with Oracle. Other PMS vendors run their own partner and key processes.

Implication: our decision register already lists "vendor REST" as one protocol option (HF-04). If the pilot hotel uses OPERA Cloud, Oracle may steer new partners to OHIP REST APIs rather than legacy FIAS. That would change which adapter we finish first.

8. Risks and Caveats

  • Licence risk. Building production code directly from Oracle's FIAS document without an Oracle agreement may breach its terms. Hence actions #3 and #4.
  • Version risk. The public FIAS document is release 2.20.25 (2022). The hotel's installed interface may differ. The vendor must confirm.
  • Profile risk. Generic HTNG schemas do not guarantee compatibility with a specific vendor's HTNG implementation.
  • Source age. Some statements about HTNG publication terms and membership offers come from older articles. htng.org and Oracle's partner page could not be loaded during this review (empty response / HTTP 403). Confirm directly before committing budget.
  • No engineering blocker. None of the above changes the current status. The module is ready, and it is waiting on vendor identification and approvals.
Bottom line HFTP is an industry association. It is not a technology provider we connect to, so there is no HFTP API key to apply for. The keys and the final specifications we need come from the hotel's PMS vendor. The fastest way forward is to confirm the vendor (HF-03). Meanwhile, we can use the free public HTNG and Oracle FIAS documents, as reference only, to reduce risk.
